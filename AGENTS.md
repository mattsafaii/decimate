# Decimate

Native Mac companion app for Affinity Designer/Photo. Affinity has no programmatic image effects and can't run Photoshop plugins, so Decimate covers that gap: algorithmic effects applied to an image and sent back into Affinity as a new layer (or exported standalone). Personal tooling; long-term vision is a full-featured distributed app with a growing effect catalog.

## v2 (shipped June 2026): Affinity bridge + refocused catalog

**Shipped.** v2 turned Decimate into the native compute engine bolted onto Affinity V3's MCP/JavaScript scripting bridge. Decimate-driven round-trip: Pull the active Affinity document full-res → apply a unique effect → Send the result back as a new layer (editable curves for vector effects, raster for dithering). The catalog refocuses on what Affinity structurally can't do; the v1 effects that just rebuilt Affinity-native filters were removed.

The spike (verified June 7 2026) drove Affinity end-to-end via the local MCP at `localhost:6767`: read the active document, wrote + read a Desktop file from inside an Affinity script. Round-trip primitives confirmed — `doc.export` (full-res out), Bitmap/PixelBuffer + `addNode` (raster in), `CurveBuilder`/`PolyCurve` (editable vector in). No native plugin needed.

**The bridge (Decimate-driven):** MCP is the control channel, a Desktop temp file is the bulk-data channel. Pull = `execute_script` → `doc.export` full-res to a Desktop temp file → load into preview. Send = render full-res → write Desktop temp file → `execute_script` to inject as a new layer (`addNode(ImageNodeDefinition)` for raster, `CurveBuilder`/`PolyCurve` for vector). Mandatory read-preamble handshake before `execute_script`. Detects unreachable MCP / `NOT_ALLOWED` / `PERMISSION_DENIED` and guides setup (Affinity's "Allow scripts to access filesystem" + AI connector enabled). Graceful "Affinity not connected" state; standalone open→effect→export still works.

## Stack

- Swift + SwiftUI, Xcode project, app name **Decimate**, bundle id `com.safaii.decimate`
- Targets current macOS, Apple Silicon
- Project is generated by xcodegen from `project.yml` — after adding/removing files, run `xcodegen generate` (never hand-edit the pbxproj)
- Python 3 + NumPy/SciPy via subprocess for numerical algorithms (no PythonKit, no sockets)
- **No third-party Swift dependencies** — the Affinity MCP client is native Swift (SSE + JSON-RPC over URLSession)
- CoreImage is available for built-in filters but no current effect uses it (`CoreImageEngine` is vestigial — it only houses `EffectError`)

## Architecture

**Effect catalog as abstraction** — each effect is a declaration: name, engine, parameter list (label, type, range, default), supported output formats. The shell renders parameter UI and routes execution from the declaration. New effects must be additive — no shell surgery.

**Engine decision rule:**
- Pure Swift for sequential per-pixel algorithms (dithering, the line effects)
- Python subprocess for numerical/vector algorithms (stippling)
- CoreImage if a needed filter exists built-in (no current effect uses it)
- Custom Metal shader if an effect is per-pixel parallel but not in CoreImage's catalog (no current effect needs Metal — future option only)

**Python bridge** — file-based CLI contract: Swift writes input image + params JSON to a temp dir, invokes the script via `Process` against the app-managed venv, reads the output file back.

**Python setup** — app creates its own venv under `~/Library/Application Support/` from bundled `python/requirements.txt` on first launch, with visible progress. Blocks Python-engine effects (not the app) until complete. Clear error if no `python3` found. Skipped on later launches.

**Stippling contract** — the Python script returns the **point list (positions + sizes)** as its result, not a finished image. Swift renders points to SVG/PNG. This keeps future custom-shape stippling a rendering-layer change only.

**Preview pipeline** — preview renders on a downsampled copy (full-res Voronoi can take minutes); export renders full resolution.

## Surfaces

- **Main window:** image preview, effect picker, parameter panel (rendered from declarations), Affinity connection-status indicator, Pull / Send / Export actions
- **First-launch setup:** venv creation with progress
- **Export panel:** save dialog offering the formats the selected effect declares (PNG for dithering; PNG + SVG for the vector effects)

## Core flow

Two paths, same effect pipeline:
- **Round-trip:** Pull active Affinity doc full-res → pick effect → adjust params (downsampled live preview) → Send full-res back as a new layer (raster, or editable curves for vector effects).
- **Standalone:** open image (picker or drag-drop) → pick effect → export full-res (PNG, or PNG + SVG for vector effects); SVG imports into Affinity as editable curves.

## Current effect catalog (see the v2 table above)

The catalog is the four v2 effects: **Vector Stipple** (Python/SciPy point list → editable dots), **Vector Engraving** and **Vector Line-screen** (Swift → editable curves), **Dithering** (Swift, palette + OKLab → raster). v1's Halftone/Noise (CoreImage) were deleted; v1's grayscale Floyd–Steinberg/Bayer were absorbed into Dithering; v1's "Stippling" became "Vector Stipple". Vector geometry output: `EffectOutput.points` (filled dots) and `.paths` (stroked/filled polylines), rendered by `StippleRenderer` / `PathRenderer`.

## No-gos (do not build these)

- Distribution packaging (signing, notarization, bundled Python runtime, installer)
- Video processing
- Batch processing of multiple images
- Custom icon/shape stippling modes (architecture leaves the door open; not built in v1)
- Affinity plugin integration — standalone companion, files move via export/import
- Effect stacking/chaining — one effect at a time
- No features beyond the Build todolist without asking Matt first
